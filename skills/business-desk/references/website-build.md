# Build around the business

Assess the [24 website areas](guides/website-creation.md) and use the [design guide](guides/website.md) and relevant expert briefs for planning, visual direction, and review. This portable workflow is adapted from the creator's working website skill. It uses the host agent's existing development tools; it does not bundle a website runtime, hosting account, or CRM.

1. Establish the actual business, customers, primary action, approved content, existing platform, and purchased scope. Use available notes before asking for information.
2. Plan the pages around the customer journey. A dealership may need inventory and inquiries, a Shopify store needs its real catalog and checkout, and a clinic may need services, providers, locations, and its intended scheduler. Trade and construction sites need service or project evidence and a useful inquiry path.
3. Define the content outline, typography, spacing, visual character, image direction, and a motif appropriate to the client. Avoid using an identical page sequence for every business.
4. Build using verified facts and approved assets. Generated imagery must not impersonate actual stock, completed projects, staff, credentials, or results.
5. Identify the data source, owner, loading state, error state, and destination for each dynamic module. Use the project's available integration tools. Additional form, booking, CRM, payment, voice, or notification skills are optional and must be installed separately if needed. Preserve working commerce and scheduling systems.
6. Keep repeated business facts in coherent data. Make the main action clear and connected to its real destination.
7. Inspect representative pages and the main journey on phone, tablet, and desktop. Verify reading order, keyboard navigation, focus, labels, contrast, and relevant error states. Use current technical documentation where behavior depends on browser or platform support.
8. Run the project build and meaningful checks after the final edit. Report the result, any prototype behavior, and unresolved integrations. Passing a local build does not establish a conversion increase.

Deliver a working implementation when authorized and supported by available tools. If access or scope limits the result, distinguish a plan, visual prototype, configured integration, and tested flow. Do not invent integrations to make a preview look finished.
